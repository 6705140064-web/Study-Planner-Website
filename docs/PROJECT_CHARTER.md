# Project Charter – Study Planner Website

## 1. Project Overview
**Project name:** Study Planner Website  
**Project type:** Startup-style web application  
**Project purpose:** Help students organize their assignments, deadlines, and study schedules in one simple website.

## 2. Problem Statement
Students often forget assignment deadlines, have difficulty organizing study time, and struggle to track which tasks are completed. The Study Planner Website aims to make these activities easier and more organized.

## 3. Project Objectives
- Allow students to create and manage study tasks.
- Let students set a due date for each task.
- Help students organize tasks in a study schedule.
- Let students track tasks as pending or completed.
- Build a simple first version that can be tested with students and improved using their feedback.

## 4. Target Users
The main users are high school, college, and university students who need help managing assignments and study time.

## 5. Minimum Viable Product (MVP)
The first version will include:
1. Create, view, edit, and delete study tasks.
2. Set a deadline for each task.
3. View tasks in a simple study schedule or task list.
4. Mark tasks as pending or completed.

**Not included in the first version:** automatic notifications, calendar synchronization, group collaboration, and AI-generated study plans. These may be considered for future versions.

## 6. Project Scope
**In scope**
- A student-friendly website interface.
- Task and deadline management.
- A basic study schedule view.
- Task completion tracking.
- Basic storage of user tasks.

**Out of scope**
- Online payments.
- Social networking.
- A mobile application.
- Integration with external calendar services.

## 7. Expected Deliverables
- Project Charter.
- Requirements Specification.
- Acceptance Criteria.
- Database Design.
- A working MVP website.
- Source code and project documentation in a public GitHub repository.

## 8. Success Measures
The MVP will be considered successful if a student can add a task, assign a deadline, view the task, and mark it as completed without errors.

## 9. Assumptions and Risks
**Assumptions**
- Users have access to a web browser and internet connection.
- Users can enter their own tasks and deadlines.

**Risks**
- Users may enter incorrect dates or incomplete task information.
- The team may have limited development time.
- Data could be lost if it is not stored correctly.
